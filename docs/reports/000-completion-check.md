## 2. 미충족 과제를 통과시키는 계획

공통 원칙(헌법·팀 규칙): 학습은 맥, 측정은 보드 B, 보드 A는 건드리지 않는다. **시험 기간 결과를 보고 모델·임계값을 다시 고르지 않는다.**
이 원칙 때문에 과제 3·4는 "같은 시험 기간에서 다시 재면 된다"가 아니다. 아래 계획은 모두 **검증 기간으로만 고르고, 시험은 아직 안 본 데이터로 한 번만** 한다.

### 과제 3: 60분 CO₂ 30% 감소 (지금 13.8%)

**왜 못 넘었나 (보고서 요약)**
- 같은 모델이 **검증 기간에서는 33% 줄였다**(73.4 vs 109.5 ppm). 기준을 넘는 실력은 있다.
- 시험 기간(9/23 ~ 10/21)에 추석 연휴와 공휴일이 겹쳐 34%가 "그대로 두면 맞는" 시간이었다. 현재값 유지 오차가 36 ppm으로 작아서 30%를 줄일 여지가 거의 없었다.
- 검증 점수 차이 0.001~0.004로 고른 변형이 시험에서는 가장 나빴다(선택 운).

**바꿀 것 (맥에서 학습, 승인 후)**
1. **선택 방법 바꾸기:** 검증 기간 하나 대신 학습 기간 안에서 28일짜리 여러 구간으로 시간 순서 교차 검증을 해서 고른다.
2. **씨앗 3개 평균(앙상블):** 실행 하나보다 안정적이다. 같은 변형에서 씨앗 차이가 1.8 ppm이었다.
3. **시점별 섞기:** 짧은 시점은 변화량 모델, 60분은 값 직접 예측 모델(시험 60분이 가장 좋았던 방식)을 쓴다. 섞는 비율은 검증으로 정한다.

**시험을 어떻게 할지 (사용자가 정할 것)**
- **A안 (권장, 공정):** 새 시험 기간을 미리 정해 두고(예: 10/22 ~ 11/04, 2주) 데이터가 쌓이면 한 번만 잰다. 수업이 있는 평일이 많아 기준 판정에 맞는 기간이다. 2주를 기다려야 한다.
- **B안 (빠름, 감점 위험):** 바꾼 모델을 같은 시험 기간에서 다시 잰다. 결과를 이미 본 기간이라 "시험 데이터로 선택" 감점(공정한 평가 10%) 위험이 있다. 하더라도 보고서에 "2차 시험"이라고 그대로 적는다.
- **결정 (2026-10-22 17:42 KST, 사용자): A안.** 2차 시험 기간을 **2026-10-22 00:00 ~ 2026-11-05 00:00 KST(끝 미포함, 14일)**로 지금 고정한다. 이 기간 데이터는 학습·선택·임계값에 쓰지 않고, 개선 모델을 검증으로 고른 기록(선택 시각)을 남긴 뒤 11/05 이후 한 번만 잰다. 1차 시험(9/23 ~ 10/21) 결과는 그대로 함께 보고한다.
- 어느 안이든 30%를 넘는다는 보장은 없다. 시험 기간이 조용하면 기준선이 너무 강하다. 그때는 "검증 33%, 시험 14%, 원인은 기간 차이"를 해석으로 내는 것이 정직한 답이다.

### 과제 4: 탐지율 80% (지금 24/35 = 69%, 28건 필요)

**놓친 11건:** 습도 값 고정 6건, 환기 정지 3건, 영점 틀어짐 2건.
습도 값 고정 6건 중 4건만 잡아도 28/35 = 80%다.

**바꿀 것 (맥, 승인 후)**
1. **습도 값 고정 규칙 추가:** 지금은 "같은 값 230칸(19시간)" 기준이라 1~4시간 고정을 못 잡는다. 대신 "**같은 공간 온도는 움직이는데 습도만 완전히 같은 값**"을 본다. 상대습도는 온도가 바뀌면 함께 바뀌므로 둘 중 하나만 멈추면 고장일 가능성이 높다. 다른 공간 습도와 비교하는 방법도 후보로 같이 본다.
2. **환기 정지 규칙(선택):** 같은 요일·시간대·비슷한 시작 CO₂의 평소 15분 상승폭을 학습 기간으로 만들고 1.8배를 넘으면 의심으로 띄운다.
3. **기준값과 임계값은 학습·검증 기간(씨앗 11)으로만 정한다.** 헛경보 ≤ 1회/일은 검증에서 지킨다.

**시험:** 지금 시험 고장(씨앗 22)은 이미 결과를 봤다. 그래서 **같은 시험 기간에 새 씨앗(예: 33)으로 고장을 새로 심어** 한 번 평가하고, 씨앗 22 결과도 함께 적는다. 고장 위치가 새로 정해지므로 "본 답을 맞히는" 일이 생기지 않는다.

### 과제 5: 사용 여부 (직접 관찰 정확도 0%)

**왜 0%인가:** 임계값이 0.95로 너무 높다. 관찰 시간 모델 확률은 최대 0.64였다. 그리고 빈 방 관찰이 없어 '비어있음→사용중' 오류율을 계산할 수 없다.

**바꿀 것**
1. **사용자 관찰 기록 추가 (사용자가 직접):** `docs/observations/occupancy.csv`에 **빈 방 구간**을 넣는다. 예: 수업 전(08:30~08:50), 점심에 아무도 없을 때, 퇴실 뒤(18:10~18:40). 사람이 있는 구간도 오후 수업으로 더 넣는다. 사용중·비어있음 각각 10칸(50분) 이상이면 비율이 의미가 생긴다.
2. **임계값 기준 바꾸기 (맥, 승인 후):** "검증 F1 최대" 대신 "**검증 기간에서 비어있음→사용중 ≤ 2%를 지키면서 재현율 최대**"로 고른다. 냉난방 제어 목적을 그대로 기준으로 쓴 것이고, 관찰 데이터를 보고 고르는 것이 아니다. 모델은 다시 학습하지 않는다.
3. **채점 (보드 B, 사용자 실행):** 관찰 기록이 쌓이면 `systemd-run --user --scope -p MemoryMax=2G .venv/bin/python -m state observe --db data/collector.db --models data/models-final/state.pkl`
- 관찰은 10-22 이후 새 데이터라 시험 기간 누수 문제가 없다.
- 단순 규칙(15분 CO₂ +30 ppm)도 관찰 6칸에서 0%였다. 빈 방 칸이 들어오면 규칙은 헛경보를, 모델은 놓침을 낼 가능성이 높아 비교가 의미 있어진다.

### 과제 7: TensorRT FP16 (🔶)

1. **사용자가 보드 B에서 확인:** `ls /usr/src/tensorrt/bin/trtexec; dpkg -l | grep -i nvinfer`. JetPack에 TensorRT 라이브러리가 이미 있으면 파이썬 모듈 없이 `trtexec --onnx=... --fp16`으로 변환·측정할 수 있다. 없으면 `sudo apt install nvidia-tensorrt`(사용자 직접, autoremove 금지).
2. **FP16 오차 대비:** GPU FP16이 1.022 ppm으로 기준을 넘었다. TensorRT도 넘으면 마지막 출력층만 FP32로 두는 방식(`--layerPrecisions`)으로 다시 잰다.
3. 측정은 `systemd-run --user --scope -p MemoryMax=2G ./edge.sh all`, 한 번에 하나.
- 지금 판정 기준(1 ppm·0.1%)은 ONNX로 이미 통과했다. 이건 "해결할 것 1"을 채우는 일이다.
