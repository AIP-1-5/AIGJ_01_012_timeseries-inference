## 2. 데이터 진단과 기준선 (과제 2)

- **가장 강한 기준선은 모든 공간·시점에서 '현재값 유지'다.** 60분 CO₂ 36.3 ppm, 온도 0.15 ℃. CO₂는 몇 분 단위로는 거의 변하지 않고, 바뀌는 순간은 하루에 몇 번뿐이기 때문이다.

## 3. 60분 예측 (과제 3)

| 구간 | 60분 CO₂ GRU / 현재값 유지 |
| --- | --- |
| 검증 기간 (8/26 ~ 9/23) | 73.4 / 109.5 ppm (**−33%**) |
| 1차 시험 기간 (9/23 ~ 10/21) | 31.3 / 36.3 ppm (−14%) |
| 온도 (1차 시험) | 0.099 / 0.146 ℃ (−33%) |

- **왜:** 시험 기간에 추석 연휴·공휴일이 겹쳐 평가 시점의 34%가 "그대로 두면 맞는" 시간이었다. 바뀔 일이 적으면 현재값 유지가 거의 정답이라 줄일 여지가 작다. 그리고 검증 점수 차이 0.001~0.004로 고른 변형이 시험에서는 가장 나빴다.
- **그래서:** 시험 결과를 보고 같은 기간에서 다시 고르지 않는다. 씨앗 평균·시점별 섞기를 검증 기간으로만 골랐다(`forecast ensemble`). 선택은 GRU 9개 평균(검증 71.4 vs 109.5 ppm, −34.8%)이다. **아직 아무도 보지 않은 2차 시험 기간(10-22 ~ 11-04)**에서 11-05 이후 한 번만 잰다. 이 기간은 10-22에 미리 고정했다.

상세 [003-forecast.md](003-forecast.md), [003-model-comparison.md](003-model-comparison.md)

## 4. 이상 탐지 (과제 4)

- 1차: 결합 탐지율 24/35 = 69%, 헛경보 0회/일. 튄 값·냉방 정지는 모두 잡고, **습도 값 고정 6건과 환기 정지 3건을 못 잡았다.**
- **왜:** 습도는 정상일 때도 몇 시간씩 같은 값이라 "같은 값 19시간" 기준으로는 1~4시간 고정을 못 잡는다. 환기 정지는 "사람이 많은 수업"과 겉모습이 같다.
- **2차:** "같은 공간 온도는 움직이는데 습도만 멈춤" 규칙(`frozen`)을 학습 기간 기준으로 추가했다. 1차 고장을 본 뒤 만든 규칙이라, 결과를 보기 전에 정한 대로 새 씨앗(33)으로 고장을 다시 심었다. **씨앗 33: 27/34 = 79%, 씨앗 22: 24/35 = 69%로 둘 다 미통과.** 놓친 습도 고정은 대부분 온도도 그대로인 밤·새벽이라 짝 비교로도 드러나지 않는다. 다음은 센서별 값 고정 판정과 새 기간 평가다.

상세 [004-anomaly.md](004-anomaly.md), [004-detection.md](004-detection.md)

## 5. 상태 추정 (과제 5)

- **환기 선제 경보는 통과:** 재현율 88.0%, macro-F1 0.626(규칙 0.608). 회의실이 77.9%로 가장 낮다.
- **사용 여부는 미통과:** 검증 F1 최대로 고른 임계값이 0.95라 사람이 있어도 "비어있음"이라고 한다(관찰 6칸 모두 놓침, 최대 확률 0.64).
- **2차:** 임계값을 "검증 기간 비어있음→사용중 ≤ 2% 중 재현율 최대"로 고르게 했지만, 0.95에서도 5.3%라 만족하는 값이 없어 0.95가 그대로 남았다. 일정 기반 정답과 실제 사용이 어긋나는 칸이 원인이라 임계값으로는 못 고친다. 판정은 직접 관찰 기준이라 **빈 방 관찰 기록이 꼭 필요하다.**

## 10. 가장 의외였던 발견과 한계

- **게이트웨이 시계가 5분 빠르다.** 메시지의 46%가 기준 시각과 60초 넘게 달랐다. 네트워크 서버 시각(nsTime)을 기준으로 둔 덕에 반응 시간 분석이 틀어지지 않았다.
- **조용한 시험 기간은 모델을 불리하게 만든다.** 같은 모델이 검증에서는 33%, 시험에서는 14% 줄였다. 평가 기간 선택이 결론을 바꿀 수 있다.
- **한계:** 센서만으로는 사람 수와 환기 고장을 구별할 수 없다. 문 열림·소음 센서, 냉난방 장비 상태(`xflow`), 회의 예약이 다음 단계다.
