# Research: 과제 3 — 60분 예측

근거: `spec.md`, 과제 2 결과(`docs/reports/002-diagnosis.md`, `002-baselines.md`), `artifacts/`, constitution v1.0.1.

## R1. 학습 장비와 라이브러리

- **Decision**: 학습은 맥(Apple Silicon)에서 PyTorch로 한다. 장치는 CPU 기본, `--device mps`로 GPU를 고를 수 있다. 의존성은 `requirements-train.txt`(`torch`)로 따로 둔다. 데이터 준비는 과제 2의 `pipeline`(pandas)을 그대로 쓴다.
- **Rationale**: 팀 역할 분담상 학습은 맥에서 한다. PyTorch는 macOS arm64용 설치 파일이 있고, 과제 7에서 ONNX로 내보내 보드(TensorRT)로 옮기기 쉽다. 모델이 작아(R4) CPU로도 한 번 학습에 수십 분이면 된다. MPS는 결과가 조금씩 달라질 수 있어 재현용 기본값은 CPU로 둔다.
- **Alternatives**: TensorFlow/Keras(팀이 덜 익숙, 보드 쪽 변환 경로가 PyTorch → ONNX보다 번거로움), 보드 B에서 학습(메모리 공유 8GB, 팀 규칙상 맥).

## R2. 표본 단위와 공간 구분

- **Decision**: 표본 = (공간, 예측 시각 t). 공간 4곳의 표본을 모두 한 모델로 학습하고, 공간을 구분하는 정보(공간 원-핫 4칸)를 입력에 넣는다. 정규화는 과제 2의 공간·항목별 평균·표준편차를 쓴다.
- **Rationale**: 공간마다 따로 학습하면 회의실처럼 표본이 적은 공간이 약하다. 공간별 정규화로 수준 차이를 없애면 "사람이 들어오면 오른다" 같은 공통 패턴을 함께 배운다. 과제 8에서 모델 하나로 운영하기 쉽다.
- **Alternatives**: 공간별 모델 4개(관리 부담, 회의실 표본 부족), 공간 구분 없이 하나(공간마다 다른 일정 패턴을 구분하지 못함).

## R3. 입력 설계

- **과거 창**: 기본 2시간(24칸). 입력 칸마다 공간의 CO₂·온도·습도(정규화) + 칸별 사용 가능 표시 3개. CO₂가 없는 공간(사무실 밖)은 CO₂ 값 0, 표시 0.
  - 이유: 과제 2에서 수업 시작 반응은 5분 안, 퇴실 뒤 감소는 몇 시간에 걸쳐 일어났다. 2시간이면 지금이 오르는 중인지 내리는 중인지, 점심 뒤인지 알 수 있다. 1·4시간은 심화(B)에서 비교한다.
  - 보간 칸은 입력에 쓴다(과제 2 규칙). 고장·결측 칸은 값 0 + 표시 0. 창의 75% 미만만 쓸 수 있으면 표본에서 뺀다(과제 2 기준선과 같은 비율).
- **미래에 알 수 있는 정보**(t+5 ~ t+60분, 12칸): 하루 시각(sin·cos), 요일(sin·cos), 일정 있는 날 여부(평일·공휴일 반영), 실습실 수업 중 여부(수업=1, 점심=0.5, 그 외=0). 입력 창 쪽에도 같은 정보를 칸마다 붙인다.
- **"일정 정보"의 정의 (일정 포함/제외 비교)**:
  - 일정 포함(`full`): 시각·요일 + 일정 있는 날 여부 + 수업 중 여부
  - 일정 제외(`no_schedule`): 시각·요일만 (공휴일·수업 시간표를 모른다)
  - 참고(`sensor_only`): 센서값만 (시각·요일도 없음)
  - `full` − `no_schedule` = 일정(시간표·공휴일)의 가치, `no_schedule` − `sensor_only` = 시각·요일의 가치
  - 이유: 시각·요일만으로도 실습실 일정의 상당 부분을 알 수 있다. 셋을 비교해야 "일정 정보가 따로 더해 주는 것"을 정직하게 잴 수 있다.
- **Alternatives**: 입력 창 1일(288칸, 학습 느림, 어제 같은 시각이 약했다는 과제 2 결과로 보면 이득이 작을 것), 날씨(외부 자료가 없음).

## R4. 출력 설계와 모델

- **Decision**:
  - 12칸(5 ~ 60분)을 한 번에 출력한다.
  - 값 자체가 아니라 **지금 값에서의 변화량** `y(t+h) − y(t)`(정규화 단위)을 CO₂·온도 두 항목에 대해 예측한다.
  - 모델: GRU(2층, hidden 64)가 과거 창을 읽고, 마지막 상태와 미래 정보(12칸 × 특성)를 이어 붙여 출력층(MLP)이 24개 값(12칸 × 2항목)을 낸다.
- **Rationale**:
  - 한 번에 출력하면 한 칸씩 반복할 때처럼 오차가 쌓이지 않고 빠르다.
  - 변화량을 예측하면 출력 0이 곧 "현재값 유지"라서 모델이 가장 강한 기준선에서 출발한다. 값 자체를 예측하면 공간별 수준을 따로 맞춰야 해서 처음에 기준선보다 나쁘기 쉽다(생각해 볼 점 2에서 둘을 비교).
  - GRU는 LSTM보다 가볍고 ONNX·TensorRT 변환이 잘 된다. 파라미터 약 5만 개라 보드에서 한 번 예측에 몇 ms 수준이다(SC-007).
- **단순한 것부터 (constitution VII)**: GRU 전에 같은 입력·같은 출력의 **선형 모델**(창을 펼쳐 한 층)을 먼저 학습한다. 선형으로도 현재값 유지를 못 이기면 입력 설계부터 다시 본다. GRU는 선형보다 나을 때만 최종 후보가 된다.
- **Alternatives**: 한 칸씩 반복(오차 누적), 값 직접 예측(비교용으로만), Transformer(데이터 대비 과함, 보드 부담), 심화(B)에서 LSTM·TCN 비교.

## R5. 손실과 정답

- **Decision**: 칸별로 정답이 관측값(보간·고장 아님)일 때만 손실에 넣는 가려진(masked) L1 손실. CO₂와 온도 손실은 정규화 단위에서 같은 비중으로 더한다.
- **Rationale**: 평가 지표가 MAE이므로 L1이 맞다. 보간 칸을 정답으로 쓰면 과제 2에서 정한 규칙(보간 값은 정답 금지)을 어긴다. 회의실 5·15분 칸은 늘 보간이라 자연히 빠진다.

## R6. 기간 사용과 누수 방지 (완료 조건 3)

- **학습 표본**: t와 t+60분이 모두 학습 기간 안. **검증 표본**: t와 t+60분이 모두 검증 기간 안. 입력 창은 앞 기간의 값을 써도 된다(과거 정보이므로).
- **시험 기간**: 학습·조기 종료·하이퍼파라미터·모델 고르기에 쓰지 않는다. 최종 모델을 고르고 `selection.json`(고른 모델, 검증 MAE, 모델 파일 해시)을 쓴 뒤에만 `evaluate --split test`가 돌아간다. 시험 평가 기록(시각, 모델 해시)을 `docs/reports/003-test-log.md`에 남기고, 같은 모델로 다시 돌리면 기록된 결과를 보여 준다.
- **정규화**: 과제 2의 `normalization.json`(학습 기간만)을 그대로 쓴다.
- **자동 시험**: (1) 학습 표본 정답 시각이 모두 학습 기간 안, (2) 검증·시험 값을 바꿔도 학습 표본이 같음, (3) `selection.json` 없이 시험 평가 거부.

## R7. 하이퍼파라미터와 고르기

- **Decision**: 기본값을 먼저 정해 두고(학습률 1e-3, 배치 512, 최대 30에폭, 검증 손실이 5에폭 동안 안 좋아지면 중단), 검증 기간으로만 작은 범위(hidden 32·64·128, 학습률 2개)를 본다. 고르는 기준은 검증 기간 60분 CO₂·온도 MAE를 각자 현재값 유지로 나눈 값의 평균이다.
- **Rationale**: 완료 조건이 60분 기준이므로 60분 성능으로 고른다. 시험 기간을 한 번도 보지 않고 정해야 시험 결과가 "처음 보는 데이터" 성적이 된다.

## R8. 평가와 비교표 (완료 조건 1·2)

- **Decision**: 시험 평가는 `artifacts/eval_points.csv`의 (공간, 시각, h)만 쓴다. 정답·지표 계산은 과제 2의 `pipeline.baselines`와 같은 함수를 쓰고, 기준선 3종과 모델을 한 표에 둔다(h × 항목 × 공간·전체·평일 수업 시간, MAE와 시점 수).
- **정합성 시험**: 변화량 0을 내는 "가짜 모델"을 평가 경로에 넣으면 과제 2의 현재값 유지 MAE와 정확히 같아야 한다. 평가 경로의 칸 맞춤(시각·h 어긋남)을 잡는 시험이다.
- **일정 포함/제외**: 세 변형 × 씨앗 3개를 같은 설정으로 학습. 시험 60분 CO₂ MAE의 평균과 범위로 "일정 정보를 넣으면 ○ppm 줄어든다"를 쓴다.
