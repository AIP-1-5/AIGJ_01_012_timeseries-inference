# Feature Specification: 과제 8 — 상시 추론 서비스

**Feature Branch**: `008-inference-service` | **Created**: 2026-10-21 | **Status**: Draft

## 완료 조건 (과제 8 확인 기준, 원문 그대로)

1. **12시간 무중단** 가동 기록
2. 가동 중 수집기를 10분 멈췄을 때 '데이터 끊김' 경보가 나고, 다시 켜면 정상으로 돌아온다
3. 조회 API로 공간별 예측·이상·상태를 받을 수 있다
4. 결과 형식 문서(토픽·필드·단위·예시)

## 요구사항

- FR-1 매분 공간마다 계산한다: 60분 예측(CO₂·온도)과 "N분 뒤 1,000 ppm 초과" 경보, 이상 점수·원인 항목·규칙 경보(데이터 끊김·값 고정·범위 밖), 사용 여부·환기 선제 경보.
- FR-2 MQTT로 발행한다. 공간별 최신 결과와 서비스 상태는 retained로 보내서 새 구독자도 바로 받게 한다. 비정상 종료는 LWT로 알린다.
- FR-3 HTTP 조회 API를 둔다: 공간 목록, 공간별 결과, N분 뒤 예측, 경보, 상태 확인(health).
- FR-4 학습 때와 같은 전처리 함수와 학습 기간 정규화 값을 쓴다(헌법 원칙 2). 모델은 보드 B에서 ONNX로 묶어(`export`) 보드 A로 복사한다. 보드 A에는 torch를 설치하지 않는다.
- FR-5 장애에 버틴다: 일부 센서 끊김은 계속 계산하면서 알리고, 공간 전체 끊김은 결과를 지어내지 않고 '데이터 끊김'으로 알린다. 계산 한 번이 실패해도 다음 주기에 다시 시도한다. systemd로 재부팅 후 자동 시작한다.
- FR-6 주기마다 처리 시간·경보·오류를 `data/service/cycles.csv`에 남기고, `summary`로 12시간 요약을 만든다.
- FR-7 결과 형식 문서 `docs/interface.md`.

## 운영 규칙

- 보드 A는 pull로 배포만 한다. 모델 파일(`data/models/`)은 커밋하지 않고 보드 B에서 복사한다.
- 수집기 10분 정지 시험은 과제 1의 24시간 측정(보드 A 10-22 14:35까지)이 끝난 뒤에 한다.
- systemd 등록(`sudo deploy/install-inference.sh`)은 sudo가 필요해 사용자가 한다. 그 전에는 tmux에서 `./service.sh run`으로 가동한다.
